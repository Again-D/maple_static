# Snapshot Policy - Maple Growth Tracker

## 1. 목적

이 문서는 Maple Growth Tracker의 일일 스냅샷 수집, 저장, 갱신, 실패 처리 정책을 정의한다.
스냅샷 정책은 차트, 성장 이벤트, 데이터 신선도 표시의 기준이 되므로 MVP 구현 전에 고정한다.

## 2. 핵심 원칙

- 캐릭터당 하루 하나의 대표 스냅샷만 유지한다.
- 날짜 기준은 한국 시간(KST, Asia/Seoul)을 사용한다.
- 같은 날짜에 여러 번 데이터를 수집하면 기존 당일 스냅샷을 갱신한다.
- 사용자는 최신 수집 시각과 데이터 부족/실패 상태를 명확히 볼 수 있어야 한다.
- 외부 API 실패는 저장된 과거 데이터를 삭제하거나 숨기지 않는다.

## 3. 날짜와 시간 기준

- S1. `snapshot_date`는 한국 시간 기준 날짜로 계산한다.
- S2. 서버의 물리적 타임존과 무관하게 서비스 로직은 `Asia/Seoul` 기준으로 오늘 날짜를 판단한다.
- S3. `created_at`, `updated_at`, `last_fetched_at` 같은 시각 필드는 timezone-aware timestamp로 저장한다.
- S4. UI의 "오늘", "어제", "최근 7일" 표현은 한국 시간 기준으로 계산한다.
- S5. 최근 7일 차트는 오늘 포함 최대 7개의 `snapshot_date`를 최신순 또는 날짜순으로 조회해 구성한다.

## 4. 자동 수집 정책

- S6. 자동 수집은 한국 시간 기준 매일 새벽 04:00 실행을 기본 정책으로 한다.
- S7. 04:00은 UI 문서의 "오늘 04:00 수집됨" 표현과 맞추기 위한 MVP 기준이다.
- S8. 자동 수집 대상은 `characters.is_auto_track = true`인 캐릭터다.
- S9. 자동 수집은 각 캐릭터의 당일 대표 스냅샷을 생성하거나 갱신한다.
- S10. 자동 수집은 일부 캐릭터 수집이 실패해도 나머지 캐릭터 수집을 계속 시도한다.
- S11. 자동 수집 실패는 기존 스냅샷을 삭제하거나 이전 날짜 스냅샷을 덮어쓰지 않는다.

## 5. 최초 검색 정책

- S12. 사용자가 처음 검색한 캐릭터가 DB에 없으면 Nexon OpenAPI에서 캐릭터 정보를 조회한다.
- S13. 조회가 성공하면 `characters`에 캐릭터 기본 정보를 저장하고 `is_auto_track`을 `true`로 설정한다.
- S14. 최초 검색 시점의 한국 날짜에 해당하는 대표 스냅샷을 생성한다.
- S15. 최초 검색으로 생성된 스냅샷은 자동 수집으로 생성된 스냅샷과 동일한 일일 대표 스냅샷으로 취급한다.
- S16. 최초 검색 시 외부 API 호출이 실패하면 캐릭터와 스냅샷을 생성하지 않는다.

## 6. 수동 새로고침 정책

- S17. 사용자는 캐릭터 대시보드에서 수동 새로고침을 요청할 수 있다.
- S18. 수동 새로고침은 Nexon OpenAPI에서 최신 캐릭터 데이터를 다시 조회한다.
- S19. 수동 새로고침이 성공하면 한국 날짜 기준 당일 대표 스냅샷을 생성하거나 갱신한다.
- S20. 같은 날짜에 이미 스냅샷이 있으면 새 row를 추가하지 않고 기존 row를 갱신한다.
- S21. 당일 대표 스냅샷 갱신 시 `characters.last_fetched_at`도 최신 수집 시각으로 갱신한다.
- S22. 수동 새로고침은 과거 날짜의 스냅샷을 수정하지 않는다.

## 7. 같은 날짜 갱신 정책

같은 날짜에 여러 번 수집된 데이터는 당일 대표 스냅샷의 최신 버전으로 본다.
MVP에서는 하루 중 변화 이력을 별도로 보관하지 않는다.

- S23. `daily_snapshots`는 `(character_id, snapshot_date)` 기준으로 upsert된다.
- S24. 같은 날짜 갱신은 레벨, 경험치, 전투력, 유니온, 헥사, 원본 JSON 필드를 최신 값으로 교체한다.
- S25. 같은 날짜 갱신은 `daily_snapshots.created_at`의 의미를 "row 최초 생성 시각"으로 유지한다.
- S26. MVP에서는 `daily_snapshots.updated_at` 컬럼이 없으므로, 최신 수집 시각은 `characters.last_fetched_at`으로 표현한다.
- S27. 하루 중 여러 번의 변화 기록이 필요한 기능은 MVP 이후 별도 수집 이력 테이블을 검토한다.

## 8. 성장 비교 기준

- S28. 성장 비교는 현재 대표 스냅샷과 그보다 이전 날짜의 가장 최신 스냅샷을 비교한다.
- S29. 같은 날짜의 이전 수집값과 현재 수집값을 비교해 이벤트를 만들지 않는다.
- S30. 첫 스냅샷만 있는 캐릭터는 비교 기준이 없으므로 성장 이벤트를 만들지 않는다.
- S31. 전투력, 레벨, 유니온, 헥사 변화의 이벤트 판정 기준은 `doc/domain/growth_event_rules.md`에서 정의한다.
- S32. 이벤트 생성은 같은 스냅샷에 대해 중복 실행되어도 동일 이벤트가 반복 표시되지 않도록 설계해야 한다.

## 9. API 실패 처리

### 9.1. 기존 데이터가 있는 경우

- S33. 외부 API 호출이 실패해도 기존 캐릭터와 기존 스냅샷을 유지한다.
- S34. 대시보드는 마지막으로 저장된 데이터를 표시하고, 최신 동기화 실패 안내를 함께 보여준다.
- S35. 실패한 수동 새로고침은 당일 스냅샷을 생성하거나 갱신하지 않는다.
- S36. 실패한 자동 수집은 해당 캐릭터의 `last_fetched_at`을 성공 시각처럼 갱신하지 않는다.

### 9.2. 기존 데이터가 없는 경우

- S37. 최초 검색에서 외부 API 호출이 실패하면 캐릭터 대시보드로 이동하지 않는다.
- S38. 사용자는 재시도 가능한 오류 상태를 본다.
- S39. 존재하지 않는 캐릭터와 일시적인 API 실패는 구분해서 표현한다.

## 10. 데이터 부족 상태

- S40. 스냅샷이 0개이면 대시보드는 표시하지 않고 검색 또는 재시도 상태를 보여준다.
- S41. 스냅샷이 1개이면 현재 상태는 표시하되 성장 차트와 타임라인은 데이터 부족 상태로 표시한다.
- S42. 스냅샷이 2개 이상이면 비교 가능한 지표에 한해 차트와 이벤트를 표시한다.
- S43. 특정 지표가 누락되면 해당 지표만 비활성 또는 데이터 없음으로 표시하고 전체 대시보드는 유지한다.

## 11. 데이터 보관 정책

- S44. MVP에서는 일일 대표 스냅샷을 별도 만료 없이 보관한다.
- S45. 원본 JSONB 필드는 Diff 계산과 향후 분석을 위해 보관한다.
- S46. Supabase 무료 플랜 용량 문제가 확인되기 전까지 자동 삭제 정책은 두지 않는다.
- S47. 장기 보관 정책과 압축/아카이빙은 MVP 이후 운영 문서에서 재검토한다.

## 12. 사용자에게 표시할 데이터 신선도

- S48. 대시보드는 마지막 성공 수집 시각을 표시한다.
- S49. 마지막 성공 수집 시각이 오늘이면 "오늘 HH:mm 수집됨" 형태로 표시한다.
- S50. 마지막 성공 수집 시각이 오늘이 아니면 날짜를 포함해 표시한다.
- S51. 최근 수집 실패가 발생했지만 기존 데이터를 표시하는 경우, 마지막 성공 수집 시각과 실패 안내를 함께 보여준다.

## 13. MVP에서 명시적으로 제외하는 것

- 하루 중 여러 번의 스냅샷 이력 보관
- 스냅샷 롤백
- 사용자별 자동 추적 설정
- 자동 추적 해제 UI
- API 실패 재시도 큐와 장기 장애 복구 작업
- 데이터 보관 기간 자동 만료
- 관리자용 수집 상태 대시보드

## 14. 수용 기준

- AC1. 한국 시간 기준 같은 날짜에 같은 캐릭터의 스냅샷 row는 하나만 존재한다.
- AC2. 최초 검색 성공 시 캐릭터와 당일 대표 스냅샷이 저장된다.
- AC3. 같은 날짜 수동 새로고침 성공 시 기존 당일 스냅샷이 갱신된다.
- AC4. 자동 수집은 한국 시간 기준 매일 04:00 실행을 기본으로 한다.
- AC5. 외부 API 실패 시 기존 데이터가 있으면 대시보드가 유지되고 실패 안내가 표시된다.
- AC6. 외부 API 실패 시 기존 데이터가 없으면 재시도 가능한 오류 상태가 표시된다.
- AC7. 첫 스냅샷만 있는 캐릭터는 성장 차트와 이벤트 타임라인에 데이터 부족 상태를 표시한다.
- AC8. 성장 비교는 같은 날짜 내 이전 수집값이 아니라 이전 날짜의 대표 스냅샷을 기준으로 한다.
