# Growth Event Rules - Maple Growth Tracker

## 1. 목적

이 문서는 일일 대표 스냅샷 사이의 차이를 어떤 성장 이벤트로 기록할지 정의한다.
MVP에서는 사용자가 최근 성장 흐름을 이해하는 데 필요한 기본 이벤트만 생성하고, 장비 옵션 상세 분석처럼 해석 비용이 큰 이벤트는 이후로 미룬다.

## 2. 기본 원칙

- 이벤트는 서로 다른 날짜의 대표 스냅샷을 비교해 생성한다.
- 같은 날짜 안에서 수동 새로고침으로 바뀐 값은 이벤트로 기록하지 않는다.
- 첫 스냅샷만 있는 캐릭터는 비교 기준이 없으므로 이벤트를 생성하지 않는다.
- 이벤트는 사용자가 읽을 수 있는 타임라인 항목이어야 한다.
- 작은 수치 흔들림은 이벤트로 남기지 않는다.
- 같은 스냅샷에 대해 같은 이벤트가 반복 생성되지 않아야 한다.

## 3. 비교 기준

- E1. 기준 스냅샷은 현재 처리 중인 `daily_snapshots` row다.
- E2. 비교 대상은 같은 캐릭터의 현재 스냅샷보다 이전 날짜 중 가장 최신 스냅샷이다.
- E3. 이전 날짜 스냅샷이 없으면 이벤트를 생성하지 않는다.
- E4. 현재 스냅샷과 이전 스냅샷의 `snapshot_date`가 같으면 이벤트를 생성하지 않는다.
- E5. 이벤트의 `event_date`는 현재 스냅샷의 `snapshot_date`와 같다.
- E6. 이벤트의 `snapshot_id`는 현재 스냅샷 ID를 가리킨다.

## 4. MVP 이벤트 타입

MVP에서 생성하는 이벤트 타입은 아래 네 가지를 우선한다.

| 이벤트 타입 | MVP 생성 여부 | 설명 |
| :--- | :--- | :--- |
| `LEVEL_UP` | 생성 | 레벨이 상승했을 때 기록한다. |
| `COMBAT_POWER_CHANGE` | 생성 | 전투력이 의미 있는 폭으로 상승 또는 하락했을 때 기록한다. |
| `HEXA_UPGRADED` | 생성 | 헥사 매트릭스 레벨 합산이 상승했을 때 기록한다. |
| `UNION_UPGRADED` | 생성 | 유니온 레벨 또는 유니온 아티팩트 레벨이 상승했을 때 기록한다. |
| `ITEM_REPLACED` | 보류 | 타입과 저장 구조는 유지하되 MVP에서는 상세 생성 규칙과 UI를 제외한다. |

## 5. 이벤트별 판정 규칙

### 5.1. 레벨업

- E7. 현재 `level`이 이전 `level`보다 크면 `LEVEL_UP` 이벤트를 생성한다.
- E8. 레벨이 2 이상 상승했으면 하나의 이벤트로 기록하고, 제목에 시작 레벨과 현재 레벨을 함께 표시한다.
- E9. 레벨이 같거나 낮아졌으면 레벨 이벤트를 생성하지 않는다.
- E10. `LEVEL_UP`의 기본 중요도는 3이다.

예시 제목:

- `Lv.285 -> Lv.286 레벨업`
- `Lv.281 -> Lv.284 레벨 상승`

### 5.2. 전투력 변화

- E11. 현재 `combat_power`와 이전 `combat_power`의 차이가 임계값 이상이면 `COMBAT_POWER_CHANGE` 이벤트를 생성한다.
- E12. MVP 전투력 변화 임계값은 절대값 100,000 이상 또는 이전 전투력 대비 1.0% 이상 중 하나를 만족하는 경우다.
- E13. 이전 전투력이 0이면 비율 기준은 적용하지 않고 절대값 기준만 적용한다.
- E14. 상승과 하락을 모두 기록하되, UI에서는 상승과 하락을 구분해 표시한다.
- E15. 전투력 변화 이벤트의 기본 중요도는 1이다.
- E16. 전투력 변화량이 1,000,000 이상 또는 5.0% 이상이면 중요도 2로 올린다.
- E17. 레벨업 이벤트와 전투력 변화 이벤트가 같은 스냅샷에서 동시에 발생해도 둘 다 기록한다.

예시 제목:

- `전투력 1,420,500 상승`
- `전투력 320,000 하락`

### 5.3. 헥사 매트릭스 상승

- E18. 현재 `hexa_matrix_level_sum`이 이전 값보다 크면 `HEXA_UPGRADED` 이벤트를 생성한다.
- E19. 증가량이 1 이상이면 하나의 이벤트로 기록한다.
- E20. 값이 같거나 낮아졌으면 헥사 이벤트를 생성하지 않는다.
- E21. 헥사 매트릭스 상승 이벤트의 기본 중요도는 2다.

예시 제목:

- `헥사 매트릭스 +3`

### 5.4. 유니온 상승

- E22. 현재 `union_level`이 이전 값보다 크면 `UNION_UPGRADED` 이벤트를 생성한다.
- E23. 현재 `union_artifact_level`이 이전 값보다 크면 `UNION_UPGRADED` 이벤트를 생성한다.
- E24. 유니온 레벨과 유니온 아티팩트 레벨이 같은 스냅샷에서 함께 상승하면 하나의 `UNION_UPGRADED` 이벤트로 합친다.
- E25. 값이 같거나 낮아졌으면 유니온 이벤트를 생성하지 않는다.
- E26. 유니온 상승 이벤트의 기본 중요도는 2다.

예시 제목:

- `유니온 레벨 +120`
- `유니온 아티팩트 +2`
- `유니온 성장 감지`

### 5.5. 장비 교체

- E27. MVP에서는 `ITEM_REPLACED` 이벤트를 자동 생성하지 않는다.
- E28. 장비 원본 JSON은 저장하지만, 장비별 동일성 판정과 옵션 Diff는 MVP 이후에 정의한다.
- E29. 장비 변경 UI는 "MVP 이후" 기능으로 남긴다.

## 6. 이벤트 상세 데이터

- E30. 모든 이벤트는 이전 값, 현재 값, 차이값을 `detail_json`에 저장할 수 있어야 한다.
- E31. `LEVEL_UP`은 이전 레벨, 현재 레벨, 증가량을 저장한다.
- E32. `COMBAT_POWER_CHANGE`는 이전 전투력, 현재 전투력, 절대 변화량, 변화율, 방향을 저장한다.
- E33. `HEXA_UPGRADED`는 이전 헥사 합산 레벨, 현재 헥사 합산 레벨, 증가량을 저장한다.
- E34. `UNION_UPGRADED`는 이전/현재 유니온 레벨과 이전/현재 유니온 아티팩트 레벨을 저장한다.
- E35. MVP에서는 `detail_json`이 UI 상세 팝업의 완전한 계약이 아니라 이벤트 생성 근거를 보존하는 용도다.

## 7. 중복 방지 정책

- E36. 같은 `snapshot_id`에 대해 같은 의미의 이벤트는 한 번만 존재해야 한다.
- E37. 이벤트 재계산은 같은 스냅샷을 여러 번 처리해도 타임라인 항목을 중복으로 늘리지 않아야 한다.
- E38. MVP의 중복 판정 키는 `snapshot_id`, `event_type`, 이벤트별 stable detail key 조합이다.
- E39. `LEVEL_UP`의 stable detail key는 `from_level -> to_level`이다.
- E40. `COMBAT_POWER_CHANGE`의 stable detail key는 `from_combat_power -> to_combat_power`다.
- E41. `HEXA_UPGRADED`의 stable detail key는 `from_hexa_sum -> to_hexa_sum`이다.
- E42. `UNION_UPGRADED`의 stable detail key는 `from_union_level/from_artifact_level -> to_union_level/to_artifact_level`이다.
- E43. 기존 DB 스키마에는 중복 방지용 유니크 제약이 없으므로, 구현 계획에서 서비스 레벨 중복 방지 또는 DB 제약 추가 여부를 결정한다.

## 8. 이벤트 제목과 설명 규칙

- E44. 이벤트 제목은 한 줄로 읽을 수 있어야 한다.
- E45. 이벤트 제목은 이벤트 타입보다 사용자가 이해하는 변화 내용을 먼저 보여준다.
- E46. 이벤트 설명은 이전 값과 현재 값을 포함할 수 있다.
- E47. 수치는 한국어 UI에서 읽기 좋게 천 단위 구분을 적용한다.
- E48. 하락 이벤트는 실패처럼 과장하지 않고 "하락" 또는 "감소"로 중립적으로 표시한다.

## 9. 중요도 규칙

| 중요도 | 의미 | MVP 예시 |
| :--- | :--- | :--- |
| 1 | 일반 변화 | 임계값을 넘는 전투력 변화 |
| 2 | 주요 성장 | 헥사 상승, 유니온 상승, 큰 전투력 변화 |
| 3 | 핵심 성장 | 레벨업 |

- E49. 중요도는 타임라인 정렬 기준이 아니라 표시 강도와 배지 스타일에 사용한다.
- E50. 같은 날짜의 이벤트는 기본적으로 생성 순서 또는 중요도 보조 기준으로 표시한다.

## 10. 이벤트 생성 제외 조건

- E51. 이전 스냅샷이 없으면 이벤트를 생성하지 않는다.
- E52. 현재 스냅샷과 이전 스냅샷의 값이 모두 없거나 0이면 이벤트를 생성하지 않는다.
- E53. 현재 값이 누락되어 비교할 수 없는 지표는 해당 지표 이벤트만 건너뛴다.
- E54. 외부 API 실패로 스냅샷이 갱신되지 않은 경우 이벤트를 생성하지 않는다.
- E55. 같은 날짜 수동 새로고침 전후 차이는 이벤트로 기록하지 않는다.

## 11. MVP 이후로 미루는 이벤트

- 장비 교체와 장비 옵션 상세 Diff
- 스타포스 변화 감지
- 잠재능력/에디셔널 잠재능력 변화 감지
- 보스 처치 이벤트
- 메소 획득량 이벤트
- 노드 성장 이벤트
- 아케인포스/어센틱포스 별도 이벤트
- 하루 중 실시간 변화 이벤트

## 12. 수용 기준

- AC1. 첫 스냅샷만 있는 캐릭터는 이벤트가 생성되지 않는다.
- AC2. 레벨이 상승하면 `LEVEL_UP` 이벤트가 생성된다.
- AC3. 전투력 변화가 100,000 이상 또는 1.0% 이상이면 `COMBAT_POWER_CHANGE` 이벤트가 생성된다.
- AC4. 전투력 변화가 임계값보다 작으면 이벤트가 생성되지 않는다.
- AC5. 헥사 매트릭스 레벨 합산이 증가하면 `HEXA_UPGRADED` 이벤트가 생성된다.
- AC6. 유니온 레벨 또는 유니온 아티팩트 레벨이 증가하면 `UNION_UPGRADED` 이벤트가 생성된다.
- AC7. 같은 스냅샷을 여러 번 처리해도 같은 이벤트가 중복 표시되지 않는다.
- AC8. MVP에서는 장비 원본 JSON이 바뀌어도 `ITEM_REPLACED` 이벤트가 자동 생성되지 않는다.
