# MVP Requirements - Maple Growth Tracker

## 1. 목적

MVP의 목표는 사용자가 메이플스토리 캐릭터 닉네임을 검색하면, 해당 캐릭터의 현재 상태와 최근 성장 흐름을 한 화면에서 확인할 수 있게 하는 것이다.
첫 버전은 "내 캐릭터가 최근 어떻게 성장했는가"를 보여주는 데 집중하며, 커뮤니티 랭킹이나 개인화 기능은 제외한다.

## 2. MVP 한 줄 정의

사용자는 캐릭터 닉네임을 검색하고, 프로필, 현재 주요 수치, 최근 7일 성장 차트, 기본 성장 이벤트 타임라인을 확인할 수 있다.

## 3. 대상 사용자

- 메이플스토리 캐릭터의 성장 추이를 날짜별로 보고 싶은 개인 유저
- 전투력, 레벨, 경험치, 유니온, 헥사 성장 흐름을 간단히 확인하고 싶은 유저
- 장비 교체나 성장 이벤트가 언제 발생했는지 나중에 되돌아보고 싶은 유저

## 4. MVP 성공 기준

- 사용자는 닉네임 검색만으로 캐릭터 대시보드에 진입할 수 있다.
- 최초 검색 시 캐릭터 기본 정보와 당일 스냅샷이 저장된다.
- 기존에 저장된 스냅샷이 2개 이상이면 최근 7일 성장 차트를 볼 수 있다.
- 이전 스냅샷과 비교 가능한 경우 기본 성장 이벤트가 타임라인에 표시된다.
- 데이터가 부족하거나 외부 API 호출이 실패해도 사용자는 현재 상태를 이해할 수 있는 화면을 본다.

## 5. 포함 범위

### 5.1. 캐릭터 검색

- R1. 사용자는 메인 화면에서 캐릭터 닉네임을 입력해 검색할 수 있다.
- R2. 검색 성공 시 해당 캐릭터의 대시보드로 이동한다.
- R3. 검색한 캐릭터가 서비스 DB에 없으면 Nexon OpenAPI에서 캐릭터 정보를 조회하고 저장한다.
- R4. 캐릭터가 존재하지 않거나 Nexon OpenAPI에서 찾을 수 없으면 명확한 실패 상태를 보여준다.

### 5.2. 캐릭터 프로필 표시

- R5. 대시보드는 캐릭터 닉네임, 월드, 직업, 레벨, 경험치 비율, 캐릭터 이미지를 표시한다.
- R6. 대시보드는 현재 전투력, 유니온 레벨, 유니온 아티팩트 레벨, 헥사 매트릭스 레벨 합산을 표시한다.
- R7. 최신 데이터 수집 시각을 표시해 사용자가 데이터 신선도를 알 수 있게 한다.

### 5.3. 스냅샷 저장

- R8. 최초 검색 또는 수동 새로고침 시 당일 캐릭터 스냅샷을 저장한다.
- R9. 캐릭터당 하루 하나의 대표 스냅샷만 유지한다.
- R10. 같은 날짜에 다시 수집한 데이터는 별도 스냅샷을 추가하지 않고 당일 대표 스냅샷을 갱신하는 방향으로 다룬다.
- R11. 등록된 캐릭터는 MVP에서 자동 추적 대상으로 저장한다.
- R12. 자동 스냅샷 수집은 한국 시간 기준 새벽 시간대에 실행하는 것을 전제로 하며, 정확한 시각은 `doc/domain/snapshot_policy.md`에서 최종 확정한다.

### 5.4. 성장 차트

- R13. 대시보드는 최근 7일 기준 성장 차트를 제공한다.
- R14. MVP 차트의 기본 지표는 전투력이다.
- R15. 레벨/경험치와 유니온 차트는 MVP에서 탭 구조를 준비하되, 구현 우선순위는 전투력 차트보다 낮다.
- R16. 저장된 스냅샷이 2개 미만이면 차트 대신 데이터가 더 쌓인 뒤 추이를 볼 수 있다는 빈 상태를 보여준다.

### 5.5. 성장 이벤트 타임라인

- R17. 이전 스냅샷과 비교 가능한 경우 성장 이벤트를 생성한다.
- R18. MVP 이벤트는 `LEVEL_UP`, `COMBAT_POWER_CHANGE`, `HEXA_UPGRADED`, `UNION_UPGRADED`를 우선 지원한다.
- R19. `ITEM_REPLACED`는 이벤트 타입과 저장 구조만 유지하고, 장비 옵션 상세 비교 UI는 MVP에서 제외한다.
- R20. 전투력 변화 이벤트는 작은 변동까지 모두 기록하지 않고, 임계값 기준을 `doc/domain/growth_event_rules.md`에서 확정한다.
- R21. 같은 스냅샷 기준으로 같은 이벤트가 반복 생성되지 않아야 한다.

### 5.6. 수동 새로고침

- R22. 대시보드는 사용자가 최신 데이터를 요청할 수 있는 새로고침 버튼을 제공한다.
- R23. 새로고침 성공 시 프로필, 최신 스냅샷, 요약 지표, 타임라인이 갱신된다.
- R24. 새로고침 실패 시 기존에 저장된 데이터가 있으면 기존 대시보드를 유지하고 실패 안내를 표시한다.
- R25. 새로고침 실패 시 기존 데이터가 없으면 대시보드 대신 복구 가능한 오류 상태를 보여준다.

### 5.7. 기본 UI 상태

- R26. 메인 화면은 닉네임 검색 입력과 서비스 목적을 간단히 보여준다.
- R27. 대시보드는 프로필 헤더, 요약 지표, 성장 차트, 이벤트 타임라인을 포함한다.
- R28. 로딩, 캐릭터 없음, API 실패, 데이터 부족 상태를 MVP에서 반드시 다룬다.
- R29. 모바일 화면에서도 검색과 핵심 대시보드 정보는 사용할 수 있어야 한다.

## 6. 제외 범위

- 로그인과 회원 계정
- 즐겨찾기, 내 캐릭터 목록, 개인화 설정
- 인기/주목받는 성장 캐릭터 TOP 5
- OpenGraph 이미지 생성
- 장비 옵션 상세 Diff 팝업
- 장비 강화 단계별 분석
- 메소 획득량, 보스 처치, 노드 성장처럼 Nexon API 스냅샷만으로 안정적으로 판단하기 어려운 이벤트
- 알림, 공유, 소셜 기능
- 관리자 페이지

## 7. 핵심 사용자 흐름

### Flow 1. 최초 캐릭터 검색

1. 사용자가 메인 화면에서 닉네임을 입력한다.
2. 서비스가 Nexon OpenAPI에서 캐릭터 정보를 조회한다.
3. 캐릭터가 존재하면 DB에 캐릭터와 당일 스냅샷을 저장한다.
4. 사용자는 캐릭터 대시보드로 이동한다.
5. 저장된 과거 스냅샷이 없으면 현재 상태와 데이터 부족 안내를 함께 본다.

### Flow 2. 기존 캐릭터 조회

1. 사용자가 이미 저장된 캐릭터 닉네임을 검색한다.
2. 서비스는 DB의 캐릭터와 최근 스냅샷을 조회한다.
3. 필요하면 최신 데이터 동기화 상태를 함께 표시한다.
4. 사용자는 최근 7일 차트와 이벤트 타임라인을 확인한다.

### Flow 3. 수동 새로고침

1. 사용자가 대시보드에서 새로고침을 누른다.
2. 서비스가 Nexon OpenAPI에서 최신 정보를 다시 조회한다.
3. 당일 대표 스냅샷을 갱신한다.
4. 이전 스냅샷과 비교 가능한 경우 이벤트 로그를 갱신한다.
5. 사용자는 갱신된 대시보드 또는 실패 안내를 본다.

## 8. 데이터 신선도와 실패 처리

- R30. 모든 대시보드에는 마지막 수집 시각이 표시되어야 한다.
- R31. 외부 API 호출 실패는 사용자에게 숨기지 않는다.
- R32. 저장된 데이터가 있는 경우 API 실패는 전체 화면 실패가 아니라 부분 실패로 처리한다.
- R33. 저장된 데이터가 없는 경우 API 실패는 재시도 가능한 오류 화면으로 처리한다.
- R34. 데이터가 부족한 차트와 타임라인은 빈 영역이 아니라 설명 있는 빈 상태로 표시한다.

## 9. MVP 이후로 미루는 기능

| 기능 | 미루는 이유 |
| :--- | :--- |
| 로그인/즐겨찾기 | MVP 가치는 검색 기반 공개 조회만으로 검증 가능하다. |
| 인기 캐릭터 | 집계 기준과 부정확한 랭킹 위험을 먼저 정의해야 한다. |
| OpenGraph | 핵심 성장 조회 흐름과 직접 관련이 낮다. |
| 장비 상세 Diff | 데이터 파싱과 UI 복잡도가 높아 기본 이벤트 이후가 적합하다. |
| 보스/메소/노드 이벤트 | 현재 스냅샷 설계만으로 안정적인 판정 근거가 부족하다. |

## 10. 후속 정의 문서

MVP 구현 전 아래 문서를 이어서 작성한다.

2. `doc/domain/growth_event_rules.md`
   - 이벤트 타입별 판정 기준, 전투력 변화 임계값, 중복 방지 규칙을 확정한다.

   - 환경 변수, 비밀값 경계, 로컬 실행, 배포 전 체크리스트를 확정한다.

## 11. 수용 기준

- AC1. 신규 사용자가 캐릭터 닉네임을 검색하면 캐릭터 기본 정보와 현재 주요 지표를 볼 수 있다.
- AC2. 최초 조회된 캐릭터는 DB에 저장되고 이후 다시 조회할 수 있다.
- AC3. 당일 스냅샷은 캐릭터당 하나만 유지된다.
- AC4. 스냅샷이 2개 이상이면 최근 7일 전투력 차트가 표시된다.
- AC5. 스냅샷이 부족하면 차트와 타임라인 영역이 의미 있는 빈 상태를 보여준다.
- AC6. 이전 스냅샷 대비 레벨업, 전투력 변화, 헥사/유니온 상승 이벤트가 감지되면 타임라인에 표시된다.
- AC7. Nexon OpenAPI 실패 시 기존 데이터가 있으면 대시보드는 유지되고 실패 안내가 표시된다.
- AC8. 로그인 없이도 전체 MVP 흐름을 사용할 수 있다.
