# UI States - Maple Growth Tracker MVP

## 1. 목적

이 문서는 Maple Growth Tracker MVP에서 사용자가 마주치는 주요 화면 상태를 정의한다.
정상 대시보드뿐 아니라 로딩, 데이터 부족, API 실패, 캐릭터 없음, 모바일 상태를 미리 고정해 프론트엔드 구현 중 임의 판단을 줄인다.

## 2. 공통 UI 원칙

- U1. 모든 상태는 사용자가 현재 무슨 일이 일어났는지 이해할 수 있어야 한다.
- U2. 복구 가능한 상태에는 재시도 또는 다시 검색할 수 있는 행동을 제공한다.
- U3. 저장된 데이터가 있으면 외부 API 실패 때문에 전체 대시보드를 숨기지 않는다.
- U4. 데이터가 부족한 영역은 빈 칸으로 두지 않고 이유와 다음 기대 상태를 표시한다.
- U5. 숫자 포맷, 부호, 상승/하락 색상은 프론트엔드에서 일관되게 처리한다.
- U6. MVP 화면은 로그인 없이 사용할 수 있다는 전제를 유지한다.

## 3. 화면 목록

| 화면 | 경로 | MVP 역할 |
| :--- | :--- | :--- |
| 메인 검색 | `/` | 캐릭터 닉네임 입력과 검색 시작 |
| 캐릭터 대시보드 | `/character/[name]` | 프로필, 최신 스냅샷, 요약, 차트, 타임라인 표시 |

## 4. 메인 검색 화면 상태

### 4.1. 기본 상태

- U7. 검색 입력창은 비어 있는 상태로 표시한다.
- U8. 검색 버튼은 입력값이 비어 있으면 비활성화한다.
- U9. MVP에서는 최근 검색 칩과 인기 캐릭터 카루셀을 표시하지 않는다.
- U10. 서비스 설명은 짧게 유지하고, 첫 화면의 중심은 닉네임 검색이어야 한다.

### 4.2. 입력 중 상태

- U11. 사용자가 닉네임을 입력하면 검색 버튼이 활성화된다.
- U12. MVP에서는 실시간 자동완성 또는 실시간 닉네임 검증을 제공하지 않는다.
- U13. 입력값 앞뒤 공백은 검색 전에 제거한다.
- U14. 비어 있는 입력으로 검색을 시도하면 입력창 주변에 간단한 안내를 표시한다.

### 4.3. 검색 로딩 상태

- U15. 검색 요청 중에는 검색 버튼을 로딩 상태로 표시하고 중복 제출을 막는다.
- U16. 검색 입력값은 유지한다.
- U17. 로딩 문구는 캐릭터 정보를 조회 중이라는 사실을 알려야 한다.

### 4.4. 캐릭터 없음 상태

- U18. `CHARACTER_NOT_FOUND` 응답이면 현재 입력값을 유지하고 캐릭터를 찾을 수 없다는 안내를 표시한다.
- U19. 캐릭터 없음 상태는 재시도 가능한 서버 오류처럼 보이면 안 된다.
- U20. 사용자는 입력값을 수정해 다시 검색할 수 있어야 한다.

### 4.5. 검색 실패 상태

- U21. `RATE_LIMITED`, `NEXON_API_FAILED`, `NEXON_API_UNAVAILABLE`, `INTERNAL_ERROR` 응답이면 재시도 가능한 오류 안내를 표시한다.
- U22. 실패 안내에는 같은 닉네임으로 다시 시도할 수 있는 액션을 제공한다.
- U23. 실패 상태에서 사용자는 입력값을 수정할 수도 있어야 한다.

## 5. 캐릭터 대시보드 기본 구성

대시보드의 MVP 구성은 아래 순서를 따른다.

1. 프로필 헤더
2. 동기화 상태와 수동 새로고침
3. 요약 지표
4. 기간/지표를 선택하는 성장 차트
5. 성장 이벤트 타임라인

- U24. 대시보드의 기본 데이터 소스는 `GET /api/v1/characters/{name}/dashboard`다.
- U25. 프론트엔드는 dashboard API가 실패했지만 기존 화면 데이터가 있으면 기존 데이터를 유지한다.
- U26. 새로고침 버튼은 프로필 헤더 근처에 둔다.
- U27. 마지막 성공 수집 시각은 항상 사용자가 볼 수 있어야 한다.

## 6. 대시보드 로딩 상태

### 6.1. 최초 진입 로딩

- U28. 대시보드 최초 진입 시 프로필, 요약 카드, 차트, 타임라인 영역에 로딩 상태를 표시한다.
- U29. 전체 화면을 비워두지 않는다.
- U30. 로딩 중에도 사용자가 어느 캐릭터를 열고 있는지 알 수 있으면 닉네임을 표시한다.

### 6.2. 수동 새로고침 로딩

- U31. 수동 새로고침 중에는 새로고침 버튼만 로딩 상태로 바꾸고 기존 대시보드는 유지한다.
- U32. 새로고침 중에는 같은 버튼의 중복 클릭을 막는다.
- U33. 수동 새로고침 로딩은 전체 페이지 로딩으로 전환하지 않는다.

## 7. 대시보드 정상 상태

- U34. 프로필 헤더는 캐릭터 이미지, 닉네임, 월드, 직업, 레벨, 경험치 비율, 전투력을 표시한다.
- U34a. 프로필 이미지는 이미지 proxy 경로를 사용하고 `object-fit: contain`으로 표시한다. 크기는 desktop 128px, mobile 112px이며 캐릭터 아트를 자르지 않는다.
- U35. 요약 지표는 기존 대시보드 기본 범위인 최근 7일 기준 전투력 변화, 레벨/경험치 변화, 헥사 변화, 유니온 변화를 표시한다.
- U36. MVP에서 장비 교체 요약 카드는 표시하지 않거나 비활성 안내로 처리한다.
- U37. 차트의 최초 선택값은 `7d` + `combatPower`다.
- U38. 기간 선택은 `7d`, `30d`, `all`, 지표 선택은 전투력, 레벨, 경험치율, 유니온 레벨, 헥사 합계를 지원한다.
- U39. selector 변경은 차트 시계열만 다시 불러오며 프로필, 요약, 타임라인은 유지한다.
- U40. 타임라인은 최신 이벤트가 위에 오도록 표시한다.
- U40a. grouped `ITEM_REPLACED` 이벤트는 슬롯별 `previousItemName -> currentItemName` 행을 표시하고, 다른 이벤트는 기존 제목/설명만 표시한다.
- U41. 이벤트는 중요도에 따라 시각적 강도를 다르게 줄 수 있지만 정렬 기준은 최신순을 우선한다.

## 8. 데이터 부족 상태

### 8.1. 스냅샷 1개

- U42. 프로필과 최신 주요 수치는 정상 표시한다.
- U43. 차트 영역에는 아직 비교할 데이터가 부족하다는 빈 상태를 표시한다.
- U44. 타임라인 영역에는 다음 스냅샷이 쌓이면 성장 이벤트가 표시된다는 안내를 표시한다.
- U45. 빈 상태는 오류처럼 보이지 않아야 한다.

### 8.2. 차트 포인트 부족

- U46. 선택한 metric의 `hasEnoughSnapshots = false`이면 해당 차트에는 metric 이름을 포함한 데이터 부족 안내를 표시한다. 요약 변화량은 `summary.hasEnoughSnapshots`를 따른다.
- U47. 단일 스냅샷 포인트만 있는 차트는 선 차트로 억지 표시하지 않는다.
- U48. 사용자가 기다리거나 수동 새로고침을 눌러야 한다고 오해하지 않도록, 일일 스냅샷이 더 필요하다는 메시지를 표시한다.

### 8.3. 이벤트 없음

- U49. 이벤트 배열이 비어 있고 스냅샷이 2개 이상이면 "아직 감지된 성장 이벤트가 없습니다" 상태를 표시한다.
- U50. 이벤트 없음은 데이터 부족과 구분한다.

## 9. API 실패 상태

### 9.1. 기존 데이터 있음

- U51. `failed_with_cache` 또는 기존 데이터가 있는 API 실패는 대시보드 상단 배너로 표시한다.
- U52. 배너는 마지막 성공 수집 시각과 최신 동기화 실패를 함께 알려야 한다.
- U53. 기존 프로필, 요약, 차트, 타임라인은 유지한다.
- U54. 사용자는 수동 새로고침을 다시 시도할 수 있어야 한다.

### 9.2. 기존 데이터 없음

- U55. `failed_empty` 또는 최초 조회 실패로 표시할 데이터가 없으면 전체 대시보드 대신 오류 상태를 표시한다.
- U56. 오류 상태에는 다시 시도와 메인 검색으로 돌아가기 액션을 제공한다.
- U57. 캐릭터 없음과 API 실패는 다른 시각 톤과 문구로 구분한다.

### 9.3. 호출 제한

- U58. `RATE_LIMITED`는 사용자의 입력 오류가 아니라 잠시 후 다시 시도해야 하는 상태로 표시한다.
- U59. 반복 클릭을 유도하지 않도록 재시도 문구는 차분하게 작성한다.

## 10. 수동 새로고침 결과 상태

- U60. 새로고침 성공 시 최신 수집 시각을 즉시 갱신한다.
- U61. 새로고침 성공으로 새 이벤트가 생성되면 타임라인에 반영한다.
- U62. 같은 날짜 새로고침은 하루 중 변화 이벤트를 새로 만들지 않는다는 정책을 따른다.
- U63. 새로고침 실패 시 버튼 로딩을 해제하고 실패 안내를 표시한다. 선택된 chart range/metric은 초기화하지 않는다.
- U64. 실패 후에도 이전 데이터는 유지한다.
- U64a. selector 변경 중에는 차트 영역만 loading 상태가 되고 나머지 대시보드와 기존 차트 context는 유지한다.

## 11. 모바일 상태

- U65. 모바일에서는 사이드바형 네비게이션을 상단 또는 하단의 간단한 네비게이션으로 바꾼다.
- U66. 프로필 헤더는 이미지, 닉네임, 월드/직업, 핵심 수치를 세로 흐름으로 배치한다.
- U67. 요약 지표 카드는 1열 또는 2열 그리드로 줄인다.
- U68. 차트는 가로 스크롤보다 반응형 폭 축소를 우선한다.
- U69. 타임라인은 날짜 라벨과 이벤트 제목이 겹치지 않아야 한다.
- U70. 새로고침 버튼은 엄지로 누르기 쉬운 위치와 크기를 가져야 한다.

## 12. 접근성과 표시 규칙

- U71. 상승/하락은 색상만으로 구분하지 않고 텍스트 부호 또는 방향 문구를 함께 표시한다.
- U72. 버튼 로딩 상태는 비활성화와 로딩 라벨을 함께 제공한다.
- U73. 오류 메시지는 사용자가 할 수 있는 다음 행동을 포함한다.
- U74. 긴 캐릭터명이나 월드/직업 텍스트는 카드 밖으로 넘치지 않아야 한다.
- U75. 차트 툴팁은 키보드 접근성 또는 대체 텍스트 전략을 구현 단계에서 검토한다.

## 13. MVP 이후로 미루는 UI

- 최근 검색 캐릭터 칩
- 인기/주목받는 성장 캐릭터 카루셀
- 장비 교체 상세 Diff 팝업 또는 서랍
- 로그인 기반 내 캐릭터 목록
- OpenGraph 미리보기 화면
- 관리자 수집 상태 화면

## 14. 수용 기준

- AC1. 메인 화면에서 비어 있는 검색은 제출되지 않는다.
- AC2. 검색 중에는 중복 제출이 막힌다.
- AC3. 캐릭터 없음과 API 실패가 서로 다른 상태로 표시된다.
- AC4. 대시보드 최초 로딩은 전체 화면 빈 상태가 아니라 주요 영역별 로딩 상태를 보여준다.
- AC5. 스냅샷 1개만 있는 캐릭터도 프로필과 현재 수치는 볼 수 있다.
- AC6. 스냅샷 부족 시 차트와 타임라인은 설명 있는 빈 상태를 보여준다.
- AC7. 수동 새로고침 실패 시 기존 대시보드 데이터가 유지된다.
- AC8. 모바일 화면에서 검색, 프로필, 요약, 차트, 타임라인이 겹치지 않는다.
